# DTS 自动走单

`auto_submit.py` 是修改后的完整 `DtsAutoSubmitService`，供现有 Django 项目集成使用。
运行时依赖原项目的 MongoDB、FTP、Dify、WeLink 及相关配置模块。

筛选与核对顺序：

1. 从 `Sheet1` 筛选 `最新状态=无影响` 且 `已走单` 为空的记录。
2. 按 `HWPSIRT ID + CVE ID` 到 `评审总表` 核对对应记录。
3. 从评审总表的 `原始CVSS评分` 列读取会议纪要文件名，保留原有 `Sheet1` 的 `是否评审=是` 条件。
4. 合并待走单记录后，检查关联基线组的完整 `Sheet1` 状态。同一 HWPSIRT ID 在组内每个基线中的所有记录都必须明确为 `无影响`。
5. 会议纪要下载和其余预检查通过后，进入原有上传、走单、历史保存、Excel 回写及通知流程。

共用基线检查在下载会议纪要、获取 Token 和实际提交前执行：

- 任意状态不等于 `无影响`（包括空白、待确认等），就拦截该共用单据。
- 缺少对应记录或组内任一基线文件未成功读取时，也不提交。
- 检查完整 `Sheet1`，不受 `已走单` 和 `是否评审` 筛选的影响；同一基线存在重复记录时，也必须全部为 `无影响`。
- 拦截结果计入预检查失败，并在日志中说明基线、状态或缺失原因。

实际提交仍按 `pbild + HWPSIRT ID` 合并；CVE ID 用于两张表的记录匹配。

## 关联基线组

关联关系是双向的，每组可包含两个、三个或更多文件，也支持多组同时配置。
组内任一文件出现非 `无影响` 状态，都阻止该组其他文件对同一单据走单；独立组互不影响。

默认根据现有的 `qg_version → pbild` 映射自动分组：

- 在 `excel_list` 中配置、且映射到相同非空 `pbild` 的版本属于同组。
- 增加文件时，更新原项目的 `excel_list` 和版本映射即可，自动检查组内全部文件。
- 按配置文件列表建组，下载失败的文件不会因此退出检查组。
- MongoDB 中存在、但没有配置到 `excel_list` 的其他版本不会自动加入检查。

`SHARED_BASELINE_GROUPS` 可补充显式关联组。当前保留已确认的 1951/1952 关联；后续可按下面的形式扩展，每个名称都是文件名去掉 `.xlsx`：

```python
# 配置形式示例；名称应替换为实际基线，相关文件也需加入 excel_list。
SHARED_BASELINE_GROUPS = (
    ("基线A", "基线B", "基线C"),
    ("基线D", "基线E"),
)
```

显式组与自动组会合并。重叠关系也会合并：例如 A/B 和 B/C 表示 A/B/C 三者互相核对，
不受文件读取顺序或哪个文件提供待走单记录的影响。
没有关联基线的版本沿用原有筛选流程。

## 本地验证

验证脚本需要 `pandas` 和 `openpyxl`，使用临时 Excel 文件和本地服务替身检查筛选规则及后续分组、预检查行为。
它不会连接真实 FTP、获取真实 Token、提交 DTS 或发送通知。

在仓库根目录运行：

```bash
python dts_api/verify_selection.py
```
